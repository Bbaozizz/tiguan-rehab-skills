# 评估课问卷与课前准备

让问卷服务于康复师的现场判断，而不是要求每个人使用同一份表单。默认快速交付课前准备；客户提醒、评估报告和 PDF 是课后可选产物，不是课前成功标准。

产物帮助康复师准备和呈现；临床决策、风险判断、检查/动作/剂量选择与解释仍由康复师负责。

## 开始前

1. 读取 `references/safety-boundaries.md`。
2. 只接收脱敏信息：使用“合成案例 A”等标签，不使用姓名、联系方式、身份证明、精确出生日期/住址、完整病历、可识别影像或机构 ID。
3. 先判断输入属于哪个模式，只执行当前模式：
   - **问卷设置模式**：有问卷题目，还没有某位客户的答案；
   - **课前准备模式**：有一位脱敏客户的问卷答案或自述；
   - **课后可选模式**：已有康复师确认的现场观察、复测结果和专业决定，且用户明确要提醒、总结或报告。
4. 缺少会改变当前产物的关键信息时，最多问 3 个问题；其余保留为未知。

## 问卷设置模式

### 1. 先读用户已有问卷

自己的问卷优先。保留原题号和问题原文，不要要求用户把自己的问卷改写成 Q01–Q10。

先确认这份问卷服务的场景：首次评估、体验评估、运动回归评估或其他明确任务。如果用户已经说明，不要再问。

### 2. 判断每道题是否改变下一步

把题目映射到下列信号，而不是套固定题数：

| 信号 | 问卷需要帮助康复师看见什么 |
| --- | --- |
| 目标 | 客户最想改变的生活、工作或运动任务 |
| 具体场景 | 问题何时、何地、在哪个环节影响最大 |
| 功能起点 | 课前已知的可观察起点和现场复测候选 |
| 客户理解 | 客户目前如何解释问题，不把它当成事实 |
| 时间与变化 | 发生时间、过程、近期变化和已尝试事项 |
| 安全与转介 | 哪些回答会阻止进入普通评估准备，交由专业人员核实 |
| 现实约束 | 时间、环境、器材、负担和其他可执行条件 |
| 补充证据 | 客户可以脱敏提供的记录、影像、报告或环境资料 |

标记下列问题：重复收集、一题多问、引导答案、选项不全/重叠、专业术语过重、无法改变任何课前准备，以及不必要的身份字段。

### 3. 交付可直接使用的问卷

输出：

1. 适用场景和这份问卷要支持的课前决定；
2. 建议保留、修改、删除和新增的题目，每项简述理由；
3. 修订后的完整问卷，保持用户适合的表单风格；
4. “题目/回答 → 课前用途 → 不得推断”映射；
5. 放入表单工具时的必答、分支和多选限制建议。

用户没有问卷时，读取 `assets/intake-questionnaire-template.md` 作为内置起步模板，再根据用户的业务场景删改。它不是所有康复师必须采用的标准问卷。

## 课前准备模式

### 1. 忠实读取任意格式的答卷

接受选择题、简答题、表格、粘贴文本或题号混合的脱敏答卷。保留原题号和问题原文，不因题号不是 Q01–Q10 而要求用户重新整理。

把输入分成四层：

- 答卷中实际写了什么；
- 客户自己相信的原因或解释；
- 康复师已明确给出的判断/限制；
- 未知与待现场验证假设。

不把未选、空白、“其他”、“暂时没有”或未收集字段解释为否定事实。安全答案出现“是 / 不确定 / 缺失”时，停止生成检查顺序、调整建议和客户提醒，只整理已知信息并标记康复师需先核实的项目。

### 2. 把答卷变成课前准备

1. 提取客户最想改变的具体任务和影响最大的环节。
2. 开场问题先引用答卷里的具体场景，证明材料已被读过；不重问已有明确答案的问题。
3. 只生成会改变评估目标、安全边界、功能基线或复测条件的现场待追问。
4. 提出 1–3 个功能基线/同条件复测候选，写清“能支持什么、不能证明什么”。
5. 把检查方向写成康复师现场可选的验证问题，不指定病理诊断、治疗手法、动作、剂量、负荷或进阶门槛。

## 课前准备默认输出

```text
1. 脱敏答卷事实卡
2. 已知 / 客户相信 / 康复师已判断 / 未知
3. 这次评估课的单一主线
4. 已经回答、不要重问的内容
5. 能证明已读材料的开场问题
6. 现场待追问与追问用途
7. 功能基线与同条件复测候选
8. 由康复师选择的现场验证问题
9. 风险、缺失证据与不得推断的内容
```

课前默认不生成客户提醒、训练/生活动作、评估总结、报告或 PDF，因为它们需要现场事实和康复师的专业决定。

## 课后可选模式

只有用户已提供康复师确认的现场观察、复测结果、已选行动及停止/联系边界，并明确要课后产物时才进入。没有现场事实时停在课前准备，不为了填满模板而假设课上发生了什么。

- **客户提醒：** 读取 `assets/client-followup-template.md`，只结构化康复师已确定的一个主行动；康复师审核并决定是否发送。
- **评估总结：** 读取 `assets/assessment-report-template.md`，将当次观察写成“支持继续验证的方向”，不写成唯一原因或长期疗效。
- **可打印 HTML/PDF：** 只在用户明确需要时读取 `references/report-schema.md`，生成 JSON 后运行：

  ```bash
  python3 scripts/render_report.py --input report.json --output report.html
  ```

打开 HTML 目检文字、换页、脱敏和边界说明，再用浏览器打印/另存为 PDF。生成了 HTML/PDF 只说明呈现链路可用，不说明临床判断已验证。

## 验收

- 问卷设置结果与用户的真实业务场景相关，不是换一套固定题号。
- 课前准备忠实保留答卷原文，没有把未知填成结论。
- 已经回答的内容不会在开场被机械重问。
- 至少一个功能基线候选可以在相同条件下重复，且明确不能证明什么。
- 课前输出没有越过现场验证生成动作、提醒或报告。
- 课后产物明确标注康复师审核，不自动发送。
- 输入和输出不包含可识别客户的信息。
