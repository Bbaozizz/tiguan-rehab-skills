# 评估课设计

将评估课设计成一个可验证的服务过程，而不是专业测试的堆叠。产物帮助康复师准备和呈现；临床决策、风险判断、测试选择与解释仍由康复师负责。

## 开始前

1. 必须读取 `references/safety-boundaries.md`。
2. 只接收脱敏信息：使用“合成案例 A”等标签，不使用姓名、联系方式、身份证明、完整病历、可识别影像或机构 ID。
3. 把输入分成四层：
   - 已确定事实；
   - 客户的自我解释；
   - 康复师已给出的判断/约束；
   - 待验证，不得写成结论的假设。
4. 如果缺少的信息会改变评估目标、安全边界或复测方式，最多问 3 个问题。其余未知直接标注，不要为填满模板而猜。

## 工作流

### 1. 建立脱敏事实卡

整理：

- 客户最想改变的一件事；
- 问题出现的具体场景、时间、动作和影响；
- 客户已经尝试过什么，自己认为原因是什么；问卷未提供时标为未知；
- 必须由康复师当面处理的风险筛查与未知信息。

如果用户还没有课前问卷，使用 `assets/intake-questionnaire-template.md` 的 10 题选择题模板。不要自动增加长文本题；业务上确实不适用的选项可删减，但不要改变对应信号的用途。

### Q01–Q10 字段映射

| 问卷答案 | 可用于 | 不得推断 |
| --- | --- | --- |
| Q01 主要区域 | 准备范围和客户原话中的部位 | 诊断或组织来源 |
| Q02–Q03 主场景与受影响最大的 1–2 个环节 | 评估课单一主线和功能基线候选 | 当次必须处理哪一项；由康复师到店后确定 |
| Q04 最先受阻方式 | 开场追问和现场观察重点 | 病理机制或风险等级 |
| Q05 最想恢复的生活 | 客户目标和报告主标题 | 客户已同意某项课程或治疗 |
| Q06 当前功能锚点 | 同一任务的起点和复测候选 | 专业检查结果 |
| Q07 评估价值标准 | 评估结束时客户最在意的验收方式 | 承诺必然达成该结果 |
| Q08–Q09 可行时段与一周把握 | 一个生活行动的现实条件 | 动作、剂量、频率或依从性结论 |
| Q10 可提供资料 | 康复师课前证据清单 | 资料内容、有效性或安全结论 |

安全筛查未由该问卷完成。Q10 的“暂时没有”只表示客户没有方便提供的补充资料，不表示“没有风险”。安全、近期变化、既往处理细节、原因解释和时间经过如未有其他可靠输入，统一列为现场待核实。

### 2. 设计“被看见”的开场

生成 3–5 个开场问题。第一句必须引用 Q02–Q03 中的具体场景和受影响环节，让客户知道材料已被读过。不要重问输入里已经回答的主要区域、主场景和受影响环节。

每个问题都要说明：要澄清什么，答案会如何改变现场验证。

### 3. 建立客户看得懂的基线

根据客户目标设计 1–3 个功能基线。每个基线必须包含：

```text
客户在意的任务
相同复测条件
可观察量（位置/时间/次数/范围/主观分数等）
需要留存的证据（文字/照片/视频，必须先有合适的知情与保存方式）
它能支持什么，不能证明什么
```

专业参数可保留给康复师，但必须额外给出一个客户能与自己生活建立关系的基线。

### 4. 设计现场验证而不是诊断

将每个现场方向写成待验证假设：

```text
已有证据
待验证假设
由康复师选择的检查/处理
复测方式
支持信号
不支持/应停止信号
```

AI 不指定病理诊断、不确定治疗手法、动作、剂量、负荷或进阶门槛。用户如果明确给出了自己的专业计划，AI 只负责整理成可执行、可记录、可复测的结构。

### 5. 把一个改变带回生活

默认只设计一个与客户当前目标直接相关的生活行动。输出：

- 什么时候做；
- 做什么（只结构化康复师已确定的动作）；
- 观察什么；
- 什么情况停止或联系专业人员；
- 下次要带回什么信息。

使用 `assets/client-followup-template.md` 起草客户提醒。它是草稿，必须由康复师审核并决定是否发送。

### 6. 生成报告

先生成结构化文稿，使用 `assets/assessment-report-template.md`。如果用户需要可打印或转成 PDF 的版本：

1. 读取 `references/report-schema.md`。
2. 生成符合契约的 JSON。
3. 运行：

   ```bash
   python3 scripts/render_report.py --input report.json --output report.html
   ```

4. 在浏览器打开 HTML，目检文字、换页、边界说明和脱敏结果。
5. 点击“打印 / 导出 PDF”，使用浏览器的“另存为 PDF”。

生成了 HTML/PDF 只说明呈现链路可用，不说明其中的临床判断已被验证。

## 默认输出

```text
1. 脱敏事实卡
2. 已知 / 客户相信 / 康复师已判断 / 待验证
3. 评估课单一主线
4. 能证明已读材料的开场问题
5. 客户可理解基线与相同条件复测
6. 待验证假设表（不代替临床计划）
7. 一个生活转移行动
8. 客户提醒草稿
9. 评估报告草稿
10. 未知、风险和下次复测
```

## 验收

- 客户能看到自己的具体生活问题，不只是一组专业参数。
- 至少一个基线可以在相同条件下重复。
- 当次变化被写成“支持继续验证的方向”，不是唯一原因或长期疗效。
- 生活行动只有一个主焦点，且有停止/联系边界。
- 报告和提醒均标明康复师审核，不自动发送。
- 输出不包含可识别客户的信息。
