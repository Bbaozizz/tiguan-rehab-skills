# 经营分析

计算规则：未检查不能记0。输入没有的字段保持 `unknown`，不用 0 填满，不在数据不完整时生成看似精确的经营结论。

没有标准表格也能开始。这个 Skill 同时负责“从哪里采、按什么口径记、什么时候分析”，不能把“请补数据”当作本次交付。

## 任务契约与第一步

只使用当前对话、附件和用户明确点名的脱敏数据或记录来源；没有上游任务契约时，只补出本轮最高需求、安全材料、最小未知和硬边界。第一个可复核输出按数据成熟度决定：有数据时给字段的已知/未知表与一个可计算指标；没有数据时给 7 天最小采集表、字段口径与第一次回看时间。缺失业务数据保持 `unknown`。

## 零数据模式：先把最小事实采起来

当用户没有表格，或只能说“最近生意不好”时，先问一个问题：

> 你的咨询、预约、实际上课、售课和消课这些数据记录在哪里？哪些现在能查到，哪些从来没记过？

根据回答完成三件事：

1. 标出微信、日历、收款记录、排课表或纸质记录中已经能查到的字段；只读用户明确提供的内容，不自行扫描或登录账号。
2. 使用 `assets/minimum-7-day-collection.csv` 生成或展示一份 7 天最小采集表，并用用户能理解的语言定义人数、次数、课时和统计周期。
3. 约定 7 天后用同一口径回看。数据不足时只说明现在无法判断什么，不提前给经营优先级。

如果用户连历史数字都没有，这次真实成果就是建立可执行的采集方式，而不是经营结论。不要要求他先学会 JSON，也不要让他为了模板重做整套账。

## 标准输入

使用 `assets/business-input.example.json` 作为字段示例。可从用户的脱敏表格映射以下字段，不要求他为了模板重做一份账：

- `inquiries` / `booked_first_sessions`：引流效率与预约转化；
- `scheduled_sessions` / `completed_sessions`：预约到店/到课完成；
- `sold_sessions` / `delivered_sold_sessions`：已售课的交付效率；
- `completed_sessions` / `checked_out_sessions`：服务完成后的消课闭环；
- 可选收入与成本字段：只在口径一致时分析。

每个数必须带统计周期、口径和来源。同一数有两个版本时先标冲突，不自选一个。

## 运行确定性计算

```bash
python3 scripts/analyze_business.py --input /path/to/business.json
```

脚本输出 JSON，包含每个指标的值、状态、分子/分母和当前优先级。分子大于分母、负数或非数值时必须停止并报数据冲突。

## 人来解释，脚本不替人拍板

按这个顺序解释：

1. **事实**：哪些字段已检查，哪些仍未知。
2. **指标**：引流效率、预约转化、交付效率、消课闭环分别是多少，分母是什么。
3. **当前优先级**：只指出一个当下最应处理的断点，并说明这是规则触发的建议，不是业绩承诺。
4. **一周验证动作**：围绕当前断点改一个变量，不同时换流量、价格、产品和交付。
5. **回看口径**：约定下次用同一口径重算的时间。

当脚本返回 `collect_data` 时，进入零数据模式或只补最小必要字段，不硬给优先级。阈值是默认诊断起点，不是行业真理；用户有明确业务阶段和历史基线时，优先用自己的基线比较。
