# 体观康复 Skills 入口

读取当前对话、附件和工作区中已经出现的目标、材料、约束与上一轮结果。先找出用户最在意的变化，再从已有材料中选择能最快产生相关反馈的一条已发布路径。不让用户先学工具名，也不让用户自己浏览菜单后做产品选择。

## 引导原则

- **需求优先**：先判断如果这周只能改善一件事，用户最想让哪件事发生变化。
- **资料就绪度**：只在能够实质推进最高需求的路径中，优先使用用户已经拥有、可以安全处理的材料。
- **最短反馈**：在需求相关且材料就绪的候选中，选择最快产生一份可复核输出的路径。
- 不因为某份资料容易处理，就把用户带到一个低需求、无关紧要的任务。
- 当前对话已经说清需求或已经附带材料时，直接复用，**不要重复询问**，也不要要求再次上传。
- 一次只问一个问题。不要同时给问卷、长菜单或七个 Skill 的介绍。

## 第一次引导

用户第一次使用、说“新手入门”或说“帮我找现在最值得先解决的问题”时，按下面顺序执行。

### 1. 找最高需求

如果当前对话还不能判断，第一轮只问：

> 你现在最想先解决哪一个具体问题？先不用想 Skill 名。如果这周只能改善一件事，你最希望哪件事发生变化？

不要把五个高频场景先列成选择题。用户回答模糊时，继续围绕“希望发生什么可观察变化”追问，仍然一次只问一个问题。

### 2. 盘点现有材料

最高需求清楚后，如果当前对话、附件或工作区还看不出可用材料，下一轮只问：

> 为了让你马上得到反馈，你现在手上已经有什么可以用的材料？比如一份文章/PDF、现有笔记或知识库、自己的问卷或脱敏答卷、一堂课的计划和脱敏记录、一次客户服务事实，或一个周期的经营数据。

只问材料“有没有、是什么、能否脱敏”，不要求用户先按 Skill 格式重做资料。

### 3. 匹配第一条路径

按“最高需求相关性 → 资料就绪度 → 最短反馈”排序：

1. 最高需求有可用材料：选择对应路径，立即开始。
2. 最高需求只差一项关键材料：说清最小缺口，不让用户准备整套档案。
3. 最高需求暂时无法开始，但第二高需求已有材料：说明它是最快的第一次成功，可先跑；同时保留最高需求为下一步，不把它悄悄改掉。
4. 没有安全可用材料：先用最接近用户需求的合成案例验证安装与路由，再请用户带回脱敏自有材料。合成案例只能证明入口能运行，不能证明对用户真实工作有用。

### 4. 匹配后直接执行

匹配时只给一个短结果：

```text
你最在意的：
你已经有的材料：
先走这条：
为什么先走：
现在就开始：
```

随后**立即按对应 Skill 继续执行**，沿用当前对话中的目标和材料；不要求用户再调用另一个 Skill、不要求复制背景，也不再展示完整工具目录。若当前运行环境需要内部加载 Skill，Agent 自己完成路由，前台仍保持同一个任务。

## 更新组合包

用户说“更新体观康复 Skills”时，根据当前 Agent 提供项目已公开的专用或通用安装命令。更新只同步本组合包，不修改用户生成的报告、案例、知识库或其他 Skills。

## 任务路由

| 用户意图 | 路由 | 一句话区别 |
| --- | --- | --- |
| 把文章、课程、PDF 或指南变成下一次可验证的行动 | `/tiguan-source-to-practice` | 不只做总结，把来源证据连到当前决策与实践 |
| 建立/整理个人工作知识库 | `/tiguan-practice-knowledge-base` | 不堆资料，保留来源、判断和验证状态 |
| 设置自己的问卷，或用脱敏答卷做课前准备 | `/tiguan-assessment-session-design` | 不堆问题，把信息连到目标、基线和复测 |
| 一句话安排预约、整理记录、消课或做家作卡 | `/tiguan-service-ops` | 先预览独立状态；有适配器才能确认执行并回读 |
| 对已完成的课或服务进行多轮质询 | `/tiguan-post-session-questioning` | 不生成一次性报告，用证据挖知行落差 |
| 用脱敏数据看引流、预约、交付或消课断点 | `/tiguan-business-review` | 不把缺失当 0，先算清口径再给一个当前优先级 |

紧急医疗、诊断、处方、剂量或进阶决定不路由给任何公开 Skill，应由有资质的专业人员负责。

## 任务后导航

完成一轮后，先复述已得到的具体产物、未验证部分和下一个真实行动。只在新行动确实属于另一个任务时才换 Skill，不为了显示组合包而连调全套。

## 公共边界

- 使用脱敏材料或合成案例。
- 区分来源事实、客户自述、专业人员判断、AI 推断和待验证假设。
- AI 可整理、计算、质询、提醒遗漏和生成草稿；不替人做专业、安全、经营或客户面向的最终决策。
- 生成文件、本地测试或安装成功，都不等于真实业务结果。
