# 客户服务运营

第一次就能得到的效果是：用户口述一次服务，Agent 把已确认内容整理成能审核的专业记录草稿和客户回家说明。真正连接系统后，核心顺序仍是 `preview -> confirm -> apply -> readback`。系统承担拆解和核对，人承担专业判断与写入确认。

## 任务契约与第一步

只使用当前对话、附件和用户明确点名的对象、材料或已声明适配器；没有上游任务契约时，补出最高需求、安全材料、最小未知和硬边界。没有客户档案或适配器时，第一个可复核输出是一次服务的未写入草稿；有适配器时，第一个可复核输出是未写入的状态预览。

## 零基础设施草稿模式

用户不需要先建立档案。请他提供一次服务的脱敏口述、课后笔记或转写；如果只有一句“帮我整理刚才这堂课”，一次只追问当前输出必需的一项信息。

默认生成：

```text
已确认事实
未知 / 需要治疗师补充
专业记录草稿
客户回家说明
治疗师已确认的下次关注点
AI 建议待治疗师确认（可选）
状态：未写入、未消课、未发送
```

专业记录草稿区分客户自述、现场观察、治疗师判断和 AI 整理。描述性事实尽量保留原话强度，不得把描述性观察改写成改善、有效、进步或因果结论；例如“第一步更顺”不能自动升级成“功能改善趋势”。未知项只写缺少的字段，不列模型猜测的身体部位、原因或候选答案。

客户回家说明只转译治疗师已经确认的目标、动作、频率与停止/联系边界；缺少哪一项就标出来，不替治疗师补齐。不得把便于理解的补充写成已确认内容，例如擅自添加使用时段、目的、因果解释、升级建议或就医边界。

“治疗师已确认的下次关注点”只记录治疗师已经说出的计划，没有明确计划时写“未提供”。本次缺口继续留在“未知 / 需要治疗师补充”，不能自动变成下次计划。模型认为值得考虑的内容只能单列为“AI 建议待治疗师确认”，不能混入正式记录或直接发给客户。草稿不是“已经建立客户档案”，也不能声称系统自动化已经跑通。

## 四个独立状态

- 预约：时间、对象、地点、状态和冲突。
- 正式记录：已确认的事实、处理、复测、家作和下次关注点。
- 消课：对应哪次服务、扣减数量、扣前/扣后余额和记录关联。
- 家庭作业卡：客户能理解的动作、频率、停止/联系边界和下次回看方式。

生成草稿不等于已写入。正式记录写入不等于已消课。消课不等于已发送客户提醒。不得用一个“已完成”合并四种状态。

## 1. Inspect

1. 只读用户明确点名的规则、对象和已声明官方操作入口；不扫描目录或查找其他对象。
2. 只读查询用户说的对象、当前预约、已有记录、课程余额和要发送的目标。
3. 缺少对象、日期、原始事实、余额或适配器能力时，留为未知，不默认为 0 或已完成。

以下第 1—4 步只适用于用户明确要求真实预约、写入、消课或发送；单纯整理一次口述时停留在草稿模式即可。

## 2. Preview

默认只输出：

```text
已核对事实
拟执行动作（逐项）
每项的 before -> after
不会执行的动作
仍缺的信息/阻塞
需要用户说出的完整确认句
当前状态：未写入
```

同时写记录和消课时，可放在同一个预览中，但确认句必须同时点名两个动作及扣减数量。

## 3. Confirm

以下条件全部满足才能写入：

- 用户已看到本轮完整预览；
- 用户给出明确授权：确认句明确点名记录、消课、预约或发送中将要执行的动作；
- 没有未解决的身份、时间、余额、对象或冲突；
- 当前工作区有已配置适配器及独立回读能力。

沉默、“好的”、“继续”或旧会话中的确认不算本轮写入授权。

## 4. Apply and readback

没有已配置适配器时，停在可直接使用的草稿、操作预览和适配需求，不伪造执行。有适配器时：

1. 只调用当前工作区已声明的官方写入入口；不手写越过运营门禁的底层写入。
2. 多个动作按顺序执行，每个动作分别记录成功/失败；部分成功时诚实报告，不静默回滚或盲目重试。
3. 从真实数据源独立回读对象、时间、记录 ID/版本、余额和发送状态。
4. 回复中逐项标明“已回读”“失败”或“未执行”，不用“整套都搞定了”代替事实。

## 专业与隐私边界

使用最小必要资料，不将真实客户数据、凭证或内部接口放入公开样例。AI 可整理和转译已确认内容，不替专业人员补诊断、动作、剂量、停止边界或客户同意。
