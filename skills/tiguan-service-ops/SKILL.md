# 客户服务运营

核心顺序：`preview -> confirm -> apply -> readback`。系统承担拆解和核对，人承担专业判断与写入确认。

## 四个独立状态

- 预约：时间、对象、地点、状态和冲突。
- 正式记录：已确认的事实、处理、复测、家作和下次关注点。
- 消课：对应哪次服务、扣减数量、扣前/扣后余额和记录关联。
- 家庭作业卡：客户能理解的动作、频率、停止/联系边界和下次回看方式。

生成草稿不等于已写入。正式记录写入不等于已消课。消课不等于已发送客户提醒。不得用一个“已完成”合并四种状态。

## 1. Inspect

1. 读当前工作区规则和已有官方操作入口。
2. 只读查询用户说的对象、当前预约、已有记录、课程余额和要发送的目标。
3. 缺少对象、日期、原始事实、余额或适配器能力时，留为未知，不默认为 0 或已完成。

## 2. Preview

默认只输出：

```text
已核对事实
拟执行动作（逐项）
每项的 before -> after
不会执行的动作
仍缺的信息/阻塞
需要用户说出的完整确认句
当前状态：未写入
```

同时写记录和消课时，可放在同一个预览中，但确认句必须同时点名两个动作及扣减数量。

## 3. Confirm

以下条件全部满足才能写入：

- 用户已看到本轮完整预览；
- 确认句明确点名记录、消课、预约或发送中将要执行的动作；
- 没有未解决的身份、时间、余额、对象或冲突；
- 当前工作区有已配置适配器及独立回读能力。

沉默、“好的”、“继续”或旧会话中的确认不算本轮写入授权。

## 4. Apply and readback

没有已配置适配器时，停在预览和适配需求，不伪造执行。有适配器时：

1. 只调用当前工作区已声明的官方写入入口；不手写越过运营门禁的底层写入。
2. 多个动作按顺序执行，每个动作分别记录成功/失败；部分成功时诚实报告，不静默回滚或盲目重试。
3. 从真实数据源独立回读对象、时间、记录 ID/版本、余额和发送状态。
4. 回复中逐项标明“已回读”“失败”或“未执行”，不用“整套都搞定了”代替事实。

## 专业与隐私边界

使用最小必要资料，不将真实客户数据、凭证或内部接口放入公开样例。AI 可整理和转译已确认内容，不替专业人员补诊断、动作、剂量、停止边界或客户同意。
