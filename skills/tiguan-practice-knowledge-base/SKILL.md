# 个人工作知识库

不以“收藏了多少资料”为成功。成功是在下一个真实问题出现时，能一跳找到相关来源、看到当时为什么这样判断，并知道它是已验证还是待验证。

个人知识库不是其他 Skill 的使用前提。用户先在当前对话里得到结果；只有当他明确希望以后复用，或相同背景已经重复解释时，才把值得保留的一项沉淀下来。

## 任务契约与第一步

只使用当前对话、附件和用户明确点名的材料；没有上游任务契约时，只补出当前条目所需的最高需求、安全材料、最小未知和硬边界。第一个可复核输出是一个含来源指针、来源事实、当事人观察和验证状态的最小条目。

## 先诊断，再新建

1. 没有现成知识库时，直接从当前对话或用户点名的一份材料生成第一个最小条目预览；不要求先设计目录树。
2. 已有知识库时，只读用户明确点名的规则、索引和目录；不得因为模板更整齐就并行新建第二套库，也不发现式扫描目录。
3. 只读检查用户现在怎么收、怎么找、怎么用，找到当前最大断点。
4. 写入前预览要新建/修改的文件和原因；用户要求建库或整理后才实施，不迁移或删除原资料。

## 最小结构

如果当前没有可用结构，使用 `assets/minimum-knowledge-base.md` 中的最小版，而不是先建复杂分类树。

每个可复用条目至少包含：

```text
标题
使用场景
来源指针
来源事实
当事人判断
当前状态：已验证 / 待验证 / 已被反证 / 仅供参考
验证记录
下次何时可复用
```

“来源指针”优先保存文件/链接、日期和页码/章节，不复制大段原文。“已验证”必须指向真实使用结果；脚本成功、文件生成和 AI 说合理都不等于已验证。

## 三种写入

- **来源笔记**：保留来源事实与指针，不冒充个人经验。
- **决策笔记**：记录一个当前判断、适用边界和下次复查条件。
- **实践记录**：记录实际做了什么、发生了什么、能否复现，用来改变验证状态。

原始材料和这三种笔记不混成一篇“完整答案”。

已验证必须指向真实使用结果；不能由文件生成、AI 推断或一次阅读替代。无法确认的状态保持未知或待验证。

## 隐私和维护

- 默认本地优先，只收最小必要内容。
- 真实客户身份、联系方式、完整病历、影像和原始对话不进入可共享知识库。
- 冲突时保留旧判断和新证据，不静默覆盖历史。
- 定期复查“待验证”和已失效条目；不为了整齐而建造更多标签、库或自动化。

## 返回入口

当前任务收束后：返回 `/tiguan-rehab` 判断新的最高需求；不得直接路由到另一个叶子 Skill。
